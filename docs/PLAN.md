# 实施计划

## 目标

交付一个可以在现代桌面浏览器运行的《三国志·天运》单机原型。首版重点验证核心循环和规则可玩性，不制作图片素材，也不进行重度渲染。

## 范围

1. 将 100 城与 135 格地图转成可验证的数据。
2. 建立独立于界面的回合制规则引擎。
3. 实现玩家对三名 AI 的完整回合循环。
4. 用 Canvas 绘制轻量棋盘，以 DOM 面板完成决策交互。
5. 为地图、经济、战斗、胜负和关键落脚事件建立自动测试。
6. 保留设计决策与实施记录，便于在 GitHub 继续迭代。

## 验收条件

- 浏览器内可以选将、开始、掷骰、购买地产、升级、挑战、攻城、使用计策和结束回合。
- AI 可以自动完成合法回合，游戏不会因资源不足或特殊格停住。
- 地图数据恰好包含 100 城和 35 个功能格。
- 经济结算不会产生 `NaN` 或负数兵力/粮草/木材。
- 达到 240 威望或仅剩一个未破产势力时能够结束游戏。
- 自动测试及语法检查通过。

## 非目标

- 在线联机、账号、服务端存档。
- 完整美术、动画、音效和移动端深度适配。
- 正式数值平衡和所有武将特技的最终版本。

## 风险与回退

- 原始规则的数据空缺以临时内容补齐，并集中记录，避免散落在代码中。
- UI 与规则引擎分离；若 Canvas 布局需要重做，可以保留全部游戏逻辑。
- 存档使用带版本号的浏览器本地数据；结构变化时可清除旧存档重新开始。
